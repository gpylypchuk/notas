# Fase 8. Publicar y validar en el mundo real

## Contribuir a proyectos reales

- [ ] Aportar código a [[Contribuciones open source - vLLM]] o [[Contribuciones open source - Triton]]
- [ ] Empezar por issues chicos etiquetados como "good first issue" antes de intentar features grandes

## Documentar el trabajo

- [ ] Escribir un post técnico documentando decisiones de arquitectura tomadas
- [ ] Incluir curvas de pérdida reales, no solo el resultado final
- [ ] Explicar qué funcionó y qué no, y por qué, no solo el camino que terminó funcionando

## Publicar

- [ ] Subir los pesos del modelo a un repo público
- [ ] Subir el código completo, no solo un notebook final limpio

> [!success] Por qué importa
> Un modelo chico bien documentado, entrenado de punta a punta, vale mucho más en una entrevista que haber corrido un notebook de Hugging Face sin entender qué pasa adentro. Esto es lo que después pesa de verdad para conseguir un rol en [[Performance engineering para modelos biomoleculares|performance engineering o ML infra]].
